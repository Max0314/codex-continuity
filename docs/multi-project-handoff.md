# 多项目同步与边界情况

## 同步范围

默认范围是一台电脑配置的固定工作区根目录，而不是单个项目或单个 Codex 任务。

```text
D:\code_CPL
  codex-continuity\
  bi_center\
  code_CPL\
  ai_code_review_web\
  ...
```

客户端统一扫描根目录下的 Git 项目，以及 `~/.codex` 中与这些项目目录关联的会话。用户不需要逐项目打开任务，也不需要发送“发布交接”或 `@MCP`。

## 两台电脑的目录

绝对路径可以不同，项目相对于工作区根目录的路径应一致。客户端使用相对路径、Git remote、分支和提交信息做映射。

```text
办公室电脑：D:\code_CPL\bi_center
公司电脑：  E:\work\code_CPL\bi_center
```

以上可以工作，但两端都使用 `D:\code_CPL` 最省心。

## 对话仍在进行

同步不会中断正在进行的 Codex 对话。每次扫描形成一个明确的时间点快照：

- 扫描前已经落盘的消息进入本次快照；
- 扫描后继续产生的消息由下一次后台检查捕获；
- 会话指纹没有变化时不会重复创建快照；
- 离开电脑前可以点击“立即同步”缩短等待时间。

## 两台电脑同时工作

Continuity 不合并或覆盖项目代码：

- GitHub/GitLab 仍是代码同步渠道；
- 快照只记录 Git 状态摘要和有限补丁；
- 远端内容只解密到 `.codex-continuity/handoffs/<id>`；
- 用户先拉取代码、核对分支和 dirty 状态，再从续接说明继续。

同一任务在两台电脑同时产生新工作时，会形成两个来源明确的快照，不自动判断哪一份覆盖另一份。

## 会话文件很大

v0.3.1 的范围与容量策略：

- 单个 Codex 会话最多 128 MiB；
- 会话原始数据软上限 450 MiB，为项目摘要、补丁和归档元数据预留空间；
- 最终 AES-256-GCM 密文包硬上限 500 MiB；
- 默认同步最近一周，可选择 2 天、5 天、一周或不限制；
- 可按项目勾选同步范围；
- 已归档会话默认不扫描，用户开启后才读取 `~/.codex/archived_sessions`；
- 不再按“最近 30 条”截断，最终由时间、项目和容量共同约束。

单会话或原始数据软上限会记录跳过原因。若最终密文包仍超过 500 MiB，客户端不会加入上传队列，并提示缩短时间范围或减少项目。内容寻址、增量分块和可恢复分片上传属于后续稳定性工作。

## 服务端离线

上传失败时，客户端把加密后的 `.ccx` 和元数据写入持久化 `outbox`。后台每分钟检查同步条件，网络恢复后先重试队列，收到服务端成功回执后才删除本地待上传项。

## 会话如何继续

- 本机会话：返回本机任务 ID 和工作目录，用户回到 Codex 中定位原任务；
- 远端会话：下载并解密只读快照，生成 `HANDOFF.md` 和建议提示词，在目标项目的新任务中继续；
- 已下载快照：再次点击续接会复用已有目录，不重复覆盖。

Continuity 不复制或合并 Codex 内部任务数据库，也不承诺跨电脑保留原生任务 ID。

## 团队使用

每位用户拥有独立账号，每台设备使用独立 API 令牌。服务端按用户隔离设备、令牌、快照元数据和密文文件。共享加密密钥只在同一用户的客户端之间传递，不交给服务器。
