# 项目分组、归档与 fribench 部署分析

日期：2026-07-27

## 1. 界面结论

当前客户端使用平铺表格。会话数量增加后，用户需要在“项目”列中反复定位，
而且在较窄窗口中会出现横向滚动，操作列不可见。

已按 Codex 的“项目 → 会话”折叠层级实施：

- 顶层显示逻辑项目，包含项目名称、会话数、待同步数和最近更新时间；
- 默认时间范围为最近一周，可切换最近 30 天或全部时间；
- 默认只展开最近使用或存在待处理项的项目，其他项目保持折叠；
- 每个项目先显示最近 4 条会话，通过“展开显示”加载更多；
- “同步整个工作区”仍是全局主操作，项目级同步作为次级操作；
- 折叠标题使用真实按钮并提供 `aria-expanded`，状态同时使用文字和颜色。

证据：

1. `01-codex-project-reference.png`：Codex 原生项目折叠参考，层级清楚。
2. `02-current-flat-list.png`：当前平铺列表，在窄窗口下需要横向滚动。

## 2. 归档会话

Codex 归档不会删除会话正文，而是把会话从活动会话目录移到
`$CODEX_HOME/archived_sessions`。

2026-07-27 的当前产品决定是：归档会话暂不进入同步范围。客户端目前只扫描：

- `$CODEX_HOME/sessions`

`$CODEX_HOME/archived_sessions` 不扫描、不上传，也不在项目分组中展示。已在服务端
存在的历史快照不会因为本地归档而自动删除。以后重新启用归档同步时，再引入
`archived` 状态、归档分组和删除墓碑机制。

## 3. 工作树

当前实现只接收 `cwd` 位于工作区根目录下的会话，因此位于
`$CODEX_HOME/worktrees` 的 Codex 托管工作树会被漏掉。

建议按 Git 身份而不是绝对路径归属项目：

- 使用 `git rev-parse --git-common-dir`、远端仓库和提交信息识别逻辑仓库；
- 托管工作树归入原项目，标记为“临时工作树”；
- 永久工作树显示为原项目下的二级环境，必要时允许独立显示；
- 保存会话、HEAD、分支或 detached 状态、补丁和未跟踪文件清单；
- 不同步 `node_modules`、构建缓存或整个工作树目录；
- 在另一台电脑上续接时创建新的本地工作树并应用补丁，不映射
  `$CODEX_HOME/worktrees` 的绝对路径；
- 如果目标分支已被其他工作树占用，使用 detached HEAD 或新的
  `continuity/<session>` 分支，避免自动抢占分支。

归档托管工作树会话后，Codex 可能清理对应目录，但会话仍可保留。Continuity
应保留最后一次加密快照，并把状态显示为“工作树需恢复”，不能把目录消失视为会话删除。

## 4. fribench 检查结果

- Ubuntu 24.04.4 LTS，Docker 29.6.2，Compose 5.3.1；
- Docker 服务和主机 Nginx 正常运行；
- 约 96 GiB 可用磁盘、6.4 GiB 可用内存；
- `8080` 已被主机 Nginx占用；
- 已有应用使用 `21000`、`21001`、`23001`、`23002`；
- UFW 已启用；
- `cpl` 用户不能直接访问 Docker socket；
- 现有免密 sudo 仅允许操作已有应用的固定 Compose 文件；
- 当前没有可复用的域名和 TLS 证书。

Codex Continuity 分配 `24001`：

- 容器映射：`127.0.0.1:24001 -> 8080`
- 临时 Nginx 入口：`10.6.0.9:24001`
- 临时公网地址：`http://1.14.72.50:24001`
- UFW 只开放该端口 48 小时，到期由 systemd timer 自动删除规则和 Nginx 站点
- `24001` 不应作为长期公网 HTTP 入口，因为登录 Cookie、API 令牌和设备认证信息
  需要 TLS 保护。

## 5. 本次临时部署决定

用户确认本次不解析域名，允许通过服务器 IP 临时直连两天。实现仍保持以下边界：

1. 为 Codex Continuity 增加窄范围 sudo 授权，只允许操作固定
   Compose 文件、Nginx 配置和对应 UFW 规则；
2. 部署目录使用
   `/srv/fribench/apps/internal/codex-continuity/releases/<version>`，
   并通过 `current` 软链接切换版本；
3. 服务端只绑定回环地址，不直接把 Docker 端口暴露到 `0.0.0.0`；
4. Nginx 和 UFW 临时开放 `24001`，48 小时后自动关闭公网入口；
5. 容器和数据仍保留在服务器中，入口关闭后可通过受控命令再次临时开放。

此方案只用于两天联调。正式商用仍应改为 HTTPS 或企业 VPN，并轮换联调期间使用的
管理员密码、设备令牌和共享加密密钥。
