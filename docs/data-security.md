# 数据与安全

## 服务端能看到什么

服务端可见：

- 用户账号、角色；
- 设备名、操作系统、客户端版本和最后心跳；
- 工作区名称；
- 交接状态、时间和密文大小；
- 客户端 API 令牌的前缀和 SHA-256 摘要。

服务端不可解密：

- Codex 会话正文；
- Git 补丁；
- `HANDOFF.md`；
- `manifest.json` 中随密文保存的完整工作状态。

管理端显示的少量 manifest 摘要由客户端作为元数据提交。不要在元数据中放置密码、密钥或聊天正文。

## 加密格式

客户端使用 32 字节用户密钥和 AES-256-GCM：

- 每份文件使用随机 96 位基础 nonce；
- 4 MiB 分块；
- 每个分块使用不同 counter nonce；
- 魔数和格式版本作为附加认证数据；
- 任意分块被篡改、截断或使用错误密钥都会解密失败。

加密密钥由两台客户端共享，不上传服务端。

## 认证

- 管理网页密码使用 Argon2id；
- 登录会话使用随机 256 位令牌，浏览器 Cookie 为 HttpOnly、SameSite=Lax；
- 生产 HTTPS 环境应设置 `CONTINUITY_COOKIE_SECURE=true`；
- 客户端 API 令牌只显示一次，服务端仅保存 SHA-256 摘要；
- 建议每台电脑使用独立令牌，丢失设备时只撤销对应令牌。

## 目录与文件权限

客户端配置默认位于：

```text
%AppData%\CodexContinuity\config.json
```

当前 MVP 使用用户文件权限保护配置。推广给同事前应增加 Windows Credential Manager/DPAPI，避免令牌和密钥以明文 JSON 保存。

服务端：

```text
/data/continuity.db
/data/blobs/*.ccx
```

容器使用非 root 用户运行。数据卷仍应使用主机磁盘加密、严格备份权限和最小暴露端口。

## 不应上传的内容

公司数据是否允许上传到个人服务器需要单独确认。即使内容已加密，仍可能受公司制度、客户合同、数据地域或审计规则限制。

后续需要增加：

- 项目 allow/deny 规则；
- 敏感目录默认拒绝；
- 最大文件、扩展名和路径过滤；
- 审计日志；
- 数据保留和删除策略；
- 密钥轮换。
