# 日常工作流程

## 一次性部署

### 私有服务器

1. 使用 Docker Compose 启动服务；
2. 通过 HTTPS 或私有 VPN 暴露服务地址；
3. 登录管理页面确认服务状态；
4. 从“桌面客户端”页下载 Windows 安装程序；
5. 普通用户在桌面客户端自行注册同步账号。

服务器不需要海外网络，也不需要访问 Codex 或 OpenAI。

### 第一台电脑

1. 安装并打开 Codex Continuity；
2. 使用用户名和密码注册账号；现有客户端会自动关联原账号与历史会话；
3. 保存首次显示的恢复密钥；
4. 在“设置”确认设备名称和工作区根目录，例如 `D:\code_CPL`；
5. 完成“连接测试”和“加密上传测试”；
6. 保持“自动同步”和“开机启动”开启。

### 第二台电脑

安装客户端并登录同一用户名和密码。客户端会自动解锁账号同步密钥，无需复制 API Token
或共享密钥。

两台电脑的绝对根目录可以不同，但项目在根目录下的相对路径应一致。为了减少映射错误，Windows 环境推荐都使用 `D:\code_CPL`。

如果忘记密码，使用登录页的“恢复密钥”入口设置新密码。恢复过程保留原有加密会话，并使
其他设备的旧登录令牌失效。

## 日常使用

正常情况下无需手动发布：

1. 在 Codex 中照常编码或分析；
2. Continuity 后台定期检查关联会话是否变化；
3. 有变化时创建加密快照；
4. 在线时立即上传，离线时保存到本机队列；
5. 网络恢复后自动重试。

需要立刻确认时，可以：

- 点击主窗口“立即同步”；
- 在托盘右键窗口点击“立即同步”；
- 使用全局快捷键 `Ctrl+Alt+P`。

不需要逐项目打开 Codex，不需要在每个任务中发送“发布交接”，也不需要 `@MCP`。

## 到另一台电脑后

1. 先通过 GitHub/GitLab 拉取项目代码；
2. 打开 Codex Continuity 的“会话”页；
3. 搜索任务标题或项目名称；
4. 点击“在此设备继续”。

两种结果：

- 本机会话：应用给出任务 ID 和工作目录，可回到 Codex 原任务继续；
- 远端会话：应用下载并解密只读快照，生成 `HANDOFF.md` 与建议提示词，在目标项目中新任务中继续。

远端续接不会修改 Codex 内部数据，也不会覆盖工作区。

## 导入与导出

- “导出离线备份”按当前同步范围生成 `.ccx` 文件，适合离线备份或受控人工传输；
- “打开加密归档”只解密到 `.codex-continuity/imports/<时间>`，不会写入 Codex 内部任务库；
- “导出诊断报告”生成脱敏 JSON，只包含版本、连接、范围、计数和错误状态，不包含凭据、
  密钥、路径、会话标题或聊天正文；
- 两台电脑必须登录同一账号。

## 托盘行为

- 左键托盘图标：打开主窗口；
- 右键托盘图标：打开快捷窗口；
- 关闭主窗口：隐藏到托盘，后台继续同步；
- 托盘“退出 Codex Continuity”：真正结束进程。
