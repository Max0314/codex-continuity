# Fribench 统一登录与加密存档

核对日期：2026-10-16。状态：已验证。业务提交 `81f8e030e43e266c1e6d3469a0d42cbdc9019697` 已推送合并并部署，Windows 0.5.0 最终安装包已发布且公网 SHA-256 与本机构建一致。Go 测试与 vet（含真实 PostgreSQL/HTTP）、9 项 Rust 测试、clippy、双前端类型检查构建和依赖审计通过。生产域名 `continuity.fribench.cn`，Compose 宿主仅监听 `127.0.0.1:24001`。

## 用户流程

网页介绍、安装包下载、本机会话浏览和本机离线归档不强制登录。网站加载同源账号 SDK，自动识别同一浏览器已有 Fribench 登录态；账号切换先清空界面，再从服务端重新读取自己的设备和快照。原运维管理员入口折叠保留，普通用户不能成为管理员，也不会自动接管旧演示账号。

桌面版 0.5.0 使用系统浏览器、PKCE S256、随机 state、仅监听 127.0.0.1 的临时端口及两分钟单次授权码。客户端不包含应用 Secret，不收集 Fribench 密码。服务端凭自己的独立凭据交换可信身份，再签发本服务令牌；访问令牌 15 分钟，刷新令牌可轮换续用 3650 天，退出立即撤销对应访问和刷新令牌。登录等待上限五分钟。

网页设置提供“退出所有桌面设备”，要求当前中央登录态、同源表单和明确确认；一次事务撤销当前账号的全部桌面会话与旧 API 令牌，不影响其他账号及密文。浏览器退出与桌面授权撤销是独立操作；桌面发现凭据失效后返回连接页，保留本机密钥、原件和离线归档。

端到端加密与登录身份分离。新账号在本机生成随机 256 位密钥，服务器只保存 SHA-256 指纹；密钥存入 Windows 凭据管理器，并要求首次离线保存恢复密钥。新设备首次解锁需要该恢复密钥，之后在本机自动解锁。Fribench 密码更改不会破坏快照加密，也不能替代恢复密钥。首次密钥在发往服务端之前先保存在本机，避免初始化提交后意外退出导致唯一密钥丢失。没有恢复密钥和已解锁设备时，服务器不能解密历史快照。

本机账号密钥、同步状态、离线队列按账号隔离；原游客及自托管目录不移动、不删除。账号首次连接关闭自动同步，普通同步以首次连接时间为基线，仅打包此后更新的会话。旧会话通过明确预览、确认的游客绑定处理，不会因登录被自动上传。

## 每服务一次游客绑定

设置页按当前项目、时间与归档范围生成一份聚合加密包。预览保存本机密文，绑定账号、本机游客安装摘要、文件 SHA-256、大小及 30 分钟有效期，此时不上传包、不消耗机会。取消仅移除本次临时预览密文，不改动 Codex 原件或其他归档。

确认上传同一包，服务端校验摘要后，在一个 PostgreSQL 事务中完成容量检查、唯一游客绑定事实与快照记录。账号已有快照拒绝覆盖；每个账号在本服务一次，每份游客安装数据不能重复认领；其他服务各自独立。失败回滚不扣次数，丢失响应可按原预览幂等重试，改变包内容的重试拒绝。正常账号保存不受一次限制。

服务端密文单包最多 500 MiB，每账号合计 2 GiB/1000 份，全服务 8 GiB；容量不足返回明确冲突，原始会话和本机离线包保留，不自动删除用户快照。上传最多两个并发流，敏感认证入口按来源限流。文件先流式接收，事务失败清理本次临时包，正常完成的文件由账号授权 API 读取。

## 部署与运维

生产元数据使用独立 `fribench_codex_continuity` PostgreSQL 数据库和角色；SQLite 只作为本机/自托管兼容，不绑定旧账号。原 `/srv/fribench/tools/codex-continuity/shared/data` 中的 SQLite 和历史密文原封保留，下载目录仍独立只读挂载。原管理员配置不覆盖，身份与数据库凭据由 `/etc/fribench/apps/codex-continuity/app.env` 单独提供。

Compose 固定完整源提交，非 root、只读文件系统、能力全丢弃、256 MiB/0.5 CPU/100 PIDs，独立业务网络和受控身份网络。Go 1.27.2、Node 24.21 构建。站点无工作区扫描权限，业务服务器不访问 Codex/OpenAI。浏览器跨域身份不从用户提供的 Header、账户 ID 或旧能力 Cookie 推断。

私有运维仓库的 allowlist 备份包括本数据库与密文目录，相册另有原件及元数据保护。恢复验证只在临时独立 PostgreSQL 内进行。自动备份不包含 work 的数据库、卷或容器；不把真实数据、密钥、环境文件或日志保存到规划目录和 Git。

## 验证与验收边界

`go test ./...`、`go vet ./...`；设置隔离 `TEST_DATABASE_URL` 执行真实 PostgreSQL 账号映射、来源身份、预览不扣次、跨账号拒绝、注入失败回滚、幂等及撤销测试。桌面 `cargo test --lib`、`cargo clippy --all-targets -- -D warnings`；前后端类型与构建、依赖审计。测试不注册真实 Fribench 用户，不占用 33 人上限。

浏览器预览可验证界面与本机模式，但不能代替两台真实 Windows 设备的系统浏览器回调、凭据管理器、恢复密钥和离线重连验收；这些列入用户验收清单，不伪称已完成真人操作。
