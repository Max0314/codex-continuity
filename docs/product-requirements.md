# 产品需求

## 目标用户

- 日常使用 Codex 编码和分析；
- 在办公室电脑和公司电脑之间来回工作；
- 同时维护多个 GitHub/GitLab 项目；
- 有一台无法访问 Codex/OpenAI 的个人云服务器；
- 后续可能把服务扩展给公司同事。

## 核心问题

Git 可以同步已提交代码，但不能完整表达：

- 当前正在处理哪些项目；
- 每个项目当前分支和未提交状态；
- 哪些 Codex 任务与工作区相关；
- 上一台电脑做到哪里；
- 接下来应该做什么；
- 是否存在尚未接管的工作快照。

## MVP 用户故事

### 服务器管理员

- 我可以用 Docker Compose 启动服务；
- 我可以登录管理网页；
- 我可以创建同事账号；
- 我可以查看设备、交接记录和存储占用；
- 我可以提供 Windows 客户端下载；
- 我不需要在服务器上配置 Codex 或海外网络。

### 普通用户

- 我可以为每台电脑创建独立令牌；
- 我只需配置一次固定工作根目录；
- 我可以一次发布所有项目，不逐个打开 Codex 任务；
- 我的内容在离开电脑前已本机加密；
- 我可以在另一台电脑查看并接管最新交接；
- 我的数据与其他同事隔离；
- 我可以切换管理端主题颜色。

## 功能范围

### 已包含

- 登录、用户和角色；
- API 令牌；
- 设备注册；
- 工作根目录 Git 扫描；
- 相关 Codex 会话只读快照；
- 本机压缩和加密；
- 服务端密文存储；
- 发布、列表、下载和接管；
- 管理网页；
- Docker Compose；
- Windows/Linux 构建产物。

### 暂不包含

- 精确迁移原 Codex 任务 ID；
- 直接修改 Codex 内部 SQLite 或全局状态；
- 自动应用 Git 补丁；
- 自动覆盖 dirty 工作树；
- Windows 托盘和开机启动；
- 断网队列；
- 代码签名与自动升级；
- 必需的 Skill、MCP 或 Plugin。

## 非功能要求

- 服务端运行时零外部 CDN；
- 服务端不调用 OpenAI；
- 客户端大文件流式处理；
- 交接内容客户端加密；
- 上传默认上限 512 MiB；
- 单用户可注册多设备；
- 多用户数据强制隔离；
- 单容器可运行；
- Windows 客户端无需安装运行时；
- 失败不得覆盖目标工作区。

## 成功标准

MVP 成功的最低标准：

1. 服务端可以用 Compose 启动并登录；
2. 两台 Windows 电脑可以分别初始化；
3. 一条命令可以发布整个工作根目录；
4. 另一台电脑可以下载、解密和生成继续入口；
5. 错误密钥无法解密；
6. 不同用户不能访问彼此交接；
7. 服务端无法读取交接正文；
8. 运行中的 Codex 对话不会被强制中断。
